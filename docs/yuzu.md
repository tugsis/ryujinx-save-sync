# Yuzu 설정 및 교차 동기화

이 문서는 소스의 `0.2.0-alpha.2` 구현에 해당합니다. 기존 `v0.1.0-alpha.1` 릴리스에는 Yuzu 기능이 없습니다. 새 소스를 빌드하거나 Yuzu를 포함한 후속 릴리스의 배포 폴더 전체를 사용하세요.

## 지원하는 구조

Yuzu의 기본 Account Save 레이아웃을 지원합니다.

```text
<NAND 루트>/user/save/0000000000000000/<32자리 사용자 ID>/<16자리 Title ID>/
```

게임마다 폴더를 입력할 필요는 없습니다. 설치본의 데이터 루트 또는 커스텀 NAND 루트를 한 번 지정하면 게임·사용자·Title ID를 탐색합니다. `account/.../1` 등 다른 레이아웃은 쓰기 지원하지 않으며 경고합니다. 0으로만 된 사용자 ID는 Account Save로 자동 등록하지 않습니다.

게임 이름은 Yuzu의 게임 목록 캐시와 이미 등록된 동일 Title ID 정보에서 읽습니다. 서버 목록을 조회하면 다른 기기에서 등록한 이름도 보완합니다. 알 수 없는 경우 Title ID를 표시합니다. Yuzu 프로필 표시명을 바이너리 DB에서 추정하지 않으며 사용자 ID를 표시합니다.

### 게임 이름이 Title ID로만 보일 때

1. Yuzu에서 게임 목록을 불러온 뒤 완전히 종료하고 RyuSync에서 게임을 다시 탐색하세요.
2. 기본적으로 `<데이터 루트>/cache/game_list/<Title ID>.appname.txt`를 읽습니다. Linux의 기본 데이터 루트에는 `$XDG_CACHE_HOME/yuzu/game_list` 또는 `~/.cache/yuzu/game_list`도 확인합니다.
3. 캐시 위치가 다르거나 NAND 루트만 지정했다면 설치본 설정의 선택 항목 **게임 이름 캐시 폴더**에 실제 `game_list` 폴더를 지정하고 저장·탐색하세요. 이미 등록한 게임 연결을 해제할 필요는 없습니다.
4. 캐시가 없거나 이름이 다르면 **내 게임 → 게임 이름 수정**으로 지정하세요. 이름은 이 기기의 같은 Title ID 목록에 우선 적용되며 재시작 후에도 유지됩니다. **자동 이름으로 되돌리기**로 직접 지정한 이름을 해제할 수 있습니다.

게임 이름 출처는 Yuzu 캐시·직접 지정·서버 목록·로컬 메타데이터로 표시합니다. 이름을 수정해도 세이브 내용·경로·슬롯·동기화 키는 바뀌지 않습니다. 다음 업로드의 표시 이름에는 반영되지만 이미 게시된 과거 revision은 다시 쓰지 않습니다. 온라인 Title DB 조회나 ROM·키 분석은 수행하지 않습니다.

캐시 형식의 근거는 [보존된 Yuzu 원본의 게임 목록 캐시 구현](https://source.hodakov.me/hdkv/yuzu/blame/commit/f1eae7d2d572599b84842ec8c677f76846611a07/src/yuzu/game_list_worker.cpp)입니다. 게임·빌드·캐시 설정에 따라 이름 파일이 없을 수 있으므로 모든 이름의 자동 발견을 보장하지는 않습니다.

`.yuzu_save_size`는 존재할 경우 16바이트 형식인지 확인합니다. 이 파일은 공통 스냅샷·게임 해시에서 제외하고 대상 Yuzu의 파일을 보존합니다. 적용 전 백업에는 관리 파일까지 포함됩니다. 하위 게임 폴더의 같은 이름이나 다른 숨김 파일은 일괄 제외하지 않습니다.

Device/System Save, 캐시, 전체 NAND, 에뮬레이터 설정·프로필 DB·키·펌웨어는 동기화하지 않습니다. Yuzu 계열 포크의 호환성도 일괄 보장하지 않습니다.

## 처음 설정하기

1. 에뮬레이터와 이전 RyuSync 백엔드를 종료합니다. 실제 세이브를 별도로 백업하세요.
2. 새 백엔드의 `serve`를 실행하고 출력된 설정 링크를 엽니다.
3. WebDAV 주소·계정·공간 이름을 저장하고 연결 테스트를 실행합니다.
4. 설정의 **추가 에뮬레이터 설치본 → 설치본 추가**에서 Yuzu를 선택합니다.
5. 이름, 사용 중인 빌드, 데이터 루트, 실제 실행 파일을 입력합니다. 커스텀 NAND를 사용하면 별도 NAND 루트를 입력합니다. 비우면 `<데이터 루트>/nand`를 사용합니다.
6. **저장 후 게임 탐색**을 누릅니다. 설정을 먼저 저장했다면 버튼 이름은 **게임 탐색**입니다. Ryujinx의 게임 탐색과 같은 기능이며, 선택한 설치본의 게임·세이브를 찾습니다.

   필수 항목은 설치본 이름·에뮬레이터 종류입니다. Yuzu 탐색에는 데이터 루트 또는 커스텀 NAND 루트 중 하나가 필요합니다. 실행 파일은 Steam 자동 실행 때만 필수이며, 빌드·작업 디렉터리·실행 인수는 선택입니다. 경로가 비어 있거나 작업 중이면 버튼 아래에 비활성 이유를 표시합니다.
7. 내 게임에서 사용자 ID와 Title ID를 확인하고 슬롯 이름을 지정해 등록합니다. 상대 기기의 같은 게임·사용자 연결에는 같은 슬롯 이름을 사용합니다. 실제 UUID를 서로 같게 바꿀 필요는 없습니다.
8. 같은 에뮬레이터끼리 먼저 동기화합니다. 처음에 양쪽 파일이 다르면 원본을 직접 선택하세요.

기본 경로 후보는 Windows `%APPDATA%/yuzu`, Linux `$XDG_DATA_HOME/yuzu` 또는 `~/.local/share/yuzu`, 실행 파일 옆 `user`, SteamOS의 `Emulation/storage/yuzu` 등입니다. 후보가 항상 실제 NAND와 일치하는 것은 아닙니다. SD카드·Portable·커스텀 경로는 실제 위치를 지정하세요.

한 PC에 설치본을 여러 개 등록할 수 있습니다. 같은 게임·슬롯을 서로 다른 설치본에 연결할 수 있지만 같은 실제 세이브 경로를 중복 등록할 수는 없습니다. 한 설치본의 서로 다른 사용자에게는 다른 슬롯을 지정하세요.

## Ryujinx ↔ Yuzu 처음 연결하기

같은 Title ID도 게임 업데이트·모드·계정 의존성 때문에 호환되지 않을 수 있습니다. 이 프로그램은 파일을 전송하며 게임 세이브 포맷이나 내부 사용자 ID를 변환하지 않습니다.

1. 양쪽에 같은 Title ID·슬롯으로 연결합니다. 가능하면 게임 업데이트 버전을 입력합니다.
2. 동기화를 요청하면 다른 에뮬레이터에서 온 이력이 있는 대상은 **호환성 확인 필요**로 보류됩니다.
3. 작업 기록의 **호환성 확인 → 백업 후 시험 적용 승인**을 누릅니다. 다시 동기화하고, 충돌이 있으면 사용할 원본을 선택합니다.
4. 게임을 해당 에뮬레이터에서 **수동으로 실행**해 로드·진행·저장이 되는지 확인한 뒤 완전히 종료합니다. 시험 상태에서는 Steam 자동 실행이 차단됩니다.
5. 내 게임의 **교차 호환성 확인 → 게임에서 로드·저장·종료 확인 완료**로 승인합니다. 비교 이후 파일이나 서버 head가 바뀌었다면 다시 비교해야 합니다.
6. 반대 에뮬레이터로 돌아갈 때도 처음에는 같은 절차로 확인합니다. 같은 PC에서 두 설치본이 같은 그룹에 연결돼 있다면 양쪽 로컬 연결을 확인해야 합니다.

승인은 출처 에뮬레이터·빌드·기록된 게임 버전 조합에 연결됩니다. 조합이 바뀌면 재승인이 필요합니다. 빌드와 게임 버전은 사용자가 입력한 값이며, ROM의 실제 업데이트를 자동 판별하지 않습니다. 빌드·게임 버전이 바뀌면 연결을 해제하고 올바른 값으로 다시 등록하세요.

게임 로드 성공 여부는 사용자가 확인합니다. 해시 일치나 파일 적용 성공을 게임 호환성 성공으로 자동 판단하지 않습니다. 로드에 실패하면 에뮬레이터를 종료하고 [백업 복구](recovery.md) 절차를 따르세요.

## 서버에만 세이브가 있을 때

1. 내 게임에서 **탐색·서버 복원 대상 설치본**을 선택합니다.
2. 서버 목록을 조회하고 원하는 버전의 **선택한 설치본에 복원 예약**을 누릅니다.
3. 선택한 에뮬레이터에서 원하는 사용자로 게임을 수동 실행하고 저장한 뒤 완전히 종료합니다. 에뮬레이터 인덱스·사용자 DB는 RyuSync가 임의 생성하지 않습니다.
4. 다시 탐색하고 해당 사용자의 **예약 복원 연결**을 누릅니다. 예약한 슬롯이 표시됩니다.
5. 동기화합니다. 교차 사용이면 시험 적용 승인도 필요합니다. 초기화 세이브는 백업하고 지정한 서버 버전을 적용하며, 초기화 세이브를 자동 업로드하지 않습니다.

예약은 재시작 후에도 유지됩니다. 예약 이후 서버 head나 저장소가 바뀌면 자동 적용·업로드를 차단합니다. 이 경우 연결을 해제한 뒤 현재 서버 버전으로 다시 예약하세요. 예약을 취소하려면 **예약 해제**를 사용합니다.

## Steam 실행 전후 동기화

설정의 **Steam 실행 프로필**에서 이름과 설치본을 선택하고 저장합니다. 그룹을 선택하지 않으면 그 설치본의 등록 게임 전체를 대상으로 합니다. 같은 그룹에 연결된 다른 로컬 설치본도 순차 비교하므로, 양쪽이 독립 변경됐다면 충돌 해결 전 실행하지 않습니다.

Steam의 대상은 RyuSync 실행 파일, 실행 옵션은 화면에 표시된 다음 형태입니다.

```text
launch --launch-profile <프로필 ID>
```

커스텀 상태 폴더를 사용했다면 `--data-dir`도 함께 지정하세요. 웹 대시보드에서도 실행 프로필을 선택해 시작할 수 있습니다. 프로필 인수는 설치본 기본 인수 뒤에 한 개씩 전달하며 셸을 거치지 않습니다.

현재 자동 실행은 EXE 또는 직접 실행하는 Linux 바이너리만 지원합니다. **AppImage 원본·Flatpak·셸 래퍼는 지원하지 않습니다.** AppImage를 사용하는 경우 직접 실행 가능한 추출 바이너리를 별도 검증하거나, 에뮬레이터를 직접 종료한 뒤 웹에서 수동 동기화하세요. 데이터 탐색·동기화 지원과 런처 지원은 별개입니다.

실행 중 웹 요청은 대기하고 종료 후 원래 대상 범위로 다시 처리합니다. RyuSync를 거치지 않고 실행한 Ryujinx/Yuzu도 프로세스 이름으로 감지해 동기화를 차단합니다. 확인되지 않은 포크·실행기 이름의 모든 경우를 추적한다고 보장하지 않습니다.

## v0.1 설정과 서버 이력 가져오기

새 기본 상태 폴더는 Windows `%LOCALAPPDATA%/RyuSync-v2`, Linux `$XDG_STATE_HOME/ryusync-v2` 또는 `~/.local/state/ryusync-v2`입니다. 새 원격 저장 영역은 `ryusync-v2/<workspace>`이며, 기존 `ryusync/<workspace>`와 분리됩니다.

1. 이전 백엔드와 Steam 바로가기를 종료합니다. 미전송·미완료 복구 작업은 이전 앱에서 먼저 해결합니다.
2. 새 기본 상태 폴더에서 백엔드를 실행합니다. 기존 `--data-dir` 또는 `RYUSYNC_DATA_DIR` 환경변수가 있으면 새 빈 폴더로 바꾸세요.
3. 설치본·게임·실행 프로필을 아직 등록하지 않은 상태에서 **이전 Ryujinx 설정 가져오기**에 이전 `state.db`의 상위 폴더를 입력합니다.
4. **설정·연결 가져오기**를 누릅니다. SQLite 백업 API로 `imports/<id>/state.db`를 보존하고, 검증한 설정·게임 연결을 한 트랜잭션으로 가져옵니다. 이전 DB·폴더·원격 이력은 변경하지 않습니다.
5. WebDAV 비밀번호를 다시 입력하고 설정을 저장합니다. **이전 v1 서버 목록 조회**에서 원하는 버전을 **빈 v2 그룹으로 가져오기**할 수 있습니다. 가져올 게임 연결이 먼저 있어야 합니다.
6. v2 그룹에 원본 revision의 출처를 기록한 새 첫 버전을 만들며, 이전 전체 DAG를 재작성하지 않습니다. baseline은 새로 비교해 설정하고 다른 로컬 진행은 충돌 선택으로 보존합니다.

이전 백업 폴더와 staging은 원래 상태 폴더에 유지되며 새 앱으로 복사하지 않습니다. 미전송·미완료 작업이 있으면 가져오기를 거부합니다. 이전 전체 폴더는 별도로 보관하세요.

v1 설정을 명시적인 `--data-dir`로 직접 열면 기존 Ryujinx 전용 동작은 유지됩니다. 그 상태에서 Yuzu 설치본을 추가할 수는 없습니다. 새 기능 사용에는 위의 별도 v2 폴더로 전환하세요. 구버전과 신버전으로 같은 로컬 세이브를 동시에 관리하면 안 됩니다.

## 검증 범위

합성 데이터로 Yuzu↔Yuzu, Ryujinx↔Yuzu 양방향 전송, 관리 파일 보존, 충돌·백업, 복원 예약, 실행 프로필, 대기 작업, 이전 DB·서버 가져오기를 검증합니다. 실제 게임·에뮬레이터 빌드·SteamOS 기기의 로드/저장 호환성은 별도 실기 검증이 필요합니다.

개발 환경 검증 명령:

```bash
npm --prefix frontend run build
dotnet build backend/RyuSync.Api
dotnet test backend/RyuSync.Tests
python3 tests/integration.py
python3 tests/yuzu_integration.py
```

Python 통합 테스트는 Linux 개발 환경용입니다. 배포본 실행에는 Python이 필요 없습니다.
