# 세이브 및 작업 복구

## 일반 충돌

웹페이지의 작업 기록에서 `버전 선택`을 엽니다. 로컬 또는 표시된 서버 버전을 선택하면 현재 상태를 다시 비교하고 새 revision을 게시합니다. 서버 버전을 고를 때도 기존 로컬 내용은 별도 revision과 적용 전 백업으로 보존합니다. 파일 이름만 보고 서로 다른 세이브 내용을 섞지 마세요.

## 업로드 실패

현재 세이브와 스냅샷을 보존합니다. WebDAV 인증·연결을 복구한 뒤 `전체 동기화`를 누르세요. 앱은 같은 저장소 범위에 속한 미전송 스냅샷을 먼저 게시한 뒤 현재 상태를 다시 비교합니다. 과거 스냅샷과 현재 내용이 서로 다르면 충돌이 발생할 수 있습니다.

`staging` 폴더를 임의로 지우면 미전송 버전을 잃을 수 있습니다. UI의 미전송 개수가 0이 되기 전에는 보존하세요.

## 이전 로컬 백업을 수동으로 복원

1. Steam과 Ryujinx, RyuSync 백엔드를 모두 종료합니다.
2. 백업 화면에 표시된 백업 경로를 확인합니다. 이 경로에는 `0`/`1`과 부가 메타데이터를 포함한 **세이브 루트 전체**가 들어 있습니다.
3. 현재 세이브 루트를 다른 위치에 복사해 추가로 보존합니다.
4. 같은 기기에서 생성된 백업의 루트 내용을 해당 세이브 루트 위치에 복원합니다. 게임·사용자·SaveDataId가 일치하는지 확인하세요. 다른 기기의 인덱스를 복사하지 마세요.
5. RyuSync를 시작하고 동기화를 요청합니다. 서버와 다른 진행 상황이면 충돌 화면에서 복원한 로컬 버전을 선택합니다. 새로운 revision으로 보관됩니다.

백업 파일을 편집하거나 기존 백업 위에 덮어쓰지 마세요. 현재는 웹의 복원 버튼을 제공하지 않습니다.

## 디렉터리 교체 중 종료

앱은 적용 전에 SQLite에 `journal` 레코드를 저장하고, 기존 디렉터리를 `.ryusync-old-<id>`, 새 디렉터리를 `.ryusync-new-<id>`로 보관합니다. 대상 경로가 없고 기존 디렉터리가 있으면 다음 시작에 기존 디렉터리를 되돌립니다. 알 수 없는 상태의 복사본은 그대로 보존하고 동기화를 차단합니다.

수동 확인 순서:

1. 백엔드와 에뮬레이터를 종료합니다.
2. 상태 폴더 전체(`state.db`, `state.db-wal`, 백업, staging)와 관련 세이브 디렉터리들을 복사하여 보존합니다.
3. 백업 또는 `.ryusync-old-<id>`에서 정상 내용을 대상 세이브 루트로 복원합니다. 어느 버전이 정상인지 확신할 수 없으면 원본을 보존한 상태로 진단하세요.
4. SQLite를 다룰 수 있는 도구에서 해당 `journal` 레코드의 `id`, `Target`, `Previous`, `BackupPath`를 확인합니다. 실제 대상 복원과 복사본 보존을 확인한 다음 **그 journal 레코드만** 삭제합니다. 레코드의 JSON 필드는 camelCase입니다.
5. 재시작해 세이브를 재탐색하고 비교합니다. 결과를 확인한 뒤 남은 임시 복사본을 정리합니다.

자동 복구 UI와 단계별 해시 검증을 통한 journal 해제는 후속 구현입니다. DB 전체나 기준 버전을 지우면 최초 연결로 인식하므로 임의 초기화는 피하세요.
