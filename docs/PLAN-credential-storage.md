# 2026-10-23 추가: 개인 기기용 파일 저장

사용자 요청에 따라 OS 보관함과 별도로 평문 파일 저장을 선택할 수 있도록 구현했다. 기존 계획의 평문 저장 제외 방침은 이 명시적 선택에 한해 변경한다. 저장 위치는 상태 폴더의 `credentials-plaintext/*.json`이며 Linux 파일 600·폴더 700 권한, 서버/계정별 분리, 재시작 자동 읽기, 저장 방식 전환·잠금·삭제를 지원한다. 일반 설정/API/로그에는 비밀번호를 반환하지 않는다. 자동 평문 fallback은 하지 않는다.

# WebDAV 비밀번호 저장 계획

- 작성일: 2026-10-22
- 상태: OS 보관함·인증 관리·웹 UI 구현 반영. 격리된 Linux 실보관함 테스트 완료, Windows 로그인/재부팅과 SteamOS Gaming Mode 실기 검증은 남아 있다.
- 대상: Windows 11 x64, SteamOS/Linux x64의 로컬 백엔드와 웹 설정 화면.
- 목적: 처음 한 번 저장한 WebDAV 비밀번호를 다음 실행에서 재사용하여, 브라우저에서 매번 입력하지 않고 Steam 실행 전·후 동기화를 수행한다.

## 1. 구현 전 동작과 변경 범위

기획 당시 `Coordinator`는 `RYUSYNC_WEBDAV_PASSWORD` 또는 `/api/storage/unlock`으로 받은 비밀번호를 메모리에만 보관했다. 일반 설정 저장이 비밀번호 입력도 적용했으며 백엔드를 재시작하면 환경변수를 제외한 인증이 사라졌다. `credentialUnlocked`는 서버의 인증 승인과 구분해야 하므로 새 구현에서는 인증 소스·보관함 상태·연결 검증 결과를 별도로 제공한다.

이번 작업은 비밀번호 보관·재조회·변경·삭제와 인증 상태 표시를 구현한다. 동기화 알고리즘, 원격 세이브 형식, 게임별 연결, 기존 버전 이력은 바꾸지 않는다. OS 로그인 사용자와 같은 사용자 세션에서 실행하며 관리자 권한을 요구하지 않는다.

| 포함 | 후속 작업 |
|---|---|
| Windows Credential Manager, Linux Secret Service | 마스터 암호 기반 대체 보관함 |
| 세션 전용 또는 기기에 저장 선택 | Google Drive OAuth 토큰 저장·갱신 |
| 재시작 후 저장된 비밀번호 읽기 | 자동 시작 등록, 컨트롤러 전용 인증 화면 |
| 인증 사용 중지, 저장 정보 삭제·교체 | 오프라인 실행 허용 정책, 네트워크 자동 재시도 |
| Steam 런처와 웹 동기화의 공통 인증 처리 | 다른 PC로 비밀번호 내보내기·동기화 |

## 2. OS별 저장 방식

| 환경 | 우선 방식 | 사용할 수 없을 때 |
|---|---|---|
| Windows 11 | 현재 사용자 Credential Manager의 Generic Credential | 저장 실패를 표시하고 명시적으로 세션 전용 사용 가능 |
| SteamOS/Linux | 사용자 세션 D-Bus의 Secret Service 기본 collection | 서비스 없음·보관함 잠김·접근 거부를 구분하고 세션 입력 제공 |

Windows는 `CredWriteW`·`CredReadW`·`CredDeleteW`·`CredFree`를 사용하는 작은 어댑터를 만든다. `CRED_TYPE_GENERIC`, `CRED_PERSIST_LOCAL_MACHINE`을 사용하여 같은 사용자의 다음 로그인에서도 읽고 다른 컴퓨터로의 로밍을 요청하지 않는다. 이 persist 값은 시스템 전체 사용자가 공유한다는 뜻이 아니다. OS 반환 버퍼를 해제하고 가능한 비밀 바이트 버퍼는 사용 후 지운다. API 근거: [CredWrite](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritea), [CredReadW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credreadw), [CREDENTIALW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw).

Linux는 Secret Service D-Bus 클라이언트 어댑터를 사용한다. 라이브러리의 라이선스·.NET 10·linux-x64 self-contained 배포 호환성을 확인한 후 의존성을 고정한다. 암호를 셸 명령 인수에 넣는 `secret-tool` 호출은 사용하지 않는다. 항목은 조회 속성으로 찾고 D-Bus object path를 영구 ID로 저장하지 않는다. 잠금 상태와 프롬프트 처리는 [Secret Service 규격](https://specifications.freedesktop.org/secret-service/latest-single/)을 따른다.

구현에서는 시스템 `libsecret-1.so.0`의 안정된 C ABI를 P/Invoke로 호출한다. 따라서 새 관리형 NuGet 의존성 없이 배포하며, libsecret·GLib/GIO 및 Secret Service 구현은 OS가 제공한다. 검색은 기본적으로 `ALL | LOAD_SECRETS`이고 사용자가 요청한 경우에만 `UNLOCK`을 추가한다. 취소 토큰은 `GCancellable`에 연결한다. Windows는 직접 Win32 API를 호출한다.

Secret Service 지원을 KWallet 또는 GNOME Keyring의 설치 여부만으로 추정하지 않는다. 실제 D-Bus 서비스 접근과 해당 collection의 읽기·쓰기 가능 여부를 확인한다. SteamOS의 Desktop/Gaming Mode에서 같은 사용자 보관함을 사용할 수 있는지는 실기 검증 대상이다. 운영체제 읽기 전용 해제나 시스템 패키지 설치를 기본 요구사항으로 만들지 않는다.

OS 보관함을 못 쓰는 경우 평문 파일, 고정 키 암호화, 암호문 옆 키 파일로 자동 대체하지 않는다. 마스터 암호 방식은 사용자 입력이 필요하므로 재부팅 후 무인 실행을 해결하는 수단으로 안내하지 않는다. 같은 사용자 권한으로 실행되는 악성 프로그램이나 관리자에 대한 완전한 비밀 보호를 보장하지 않는다.

## 3. 저장 대상과 연결 구분

- 비밀값은 WebDAV 비밀번호 또는 앱 비밀번호다. URL·계정·공간 등 기존 설정과 구분하여 OS 보관함에만 영구 저장한다.
- 상태 폴더마다 임의 `credentialNamespace`를 한 번 생성한다. 로컬 DB에는 namespace, 보관함 종류, 불투명 항목 ID, 연결 식별 해시, 스키마 버전과 정리 대기 ID만 저장한다. 비밀번호·복호화 키는 저장하지 않는다.
- 연결 식별자는 **WebDAV 엔드포인트와 사용자 이름**으로 만든다. scheme·host·기본 port는 URI 규칙으로 정규화하고 경로는 대소문자·의미를 보존한다. 현행 WebDAV 어댑터와 같은 끝 `/` 처리만 허용하고, 다른 경로·계정이 합쳐지지 않게 테스트한다. userinfo·fragment·미지원 query는 거부한다.
- 동기화 workspace와 프로토콜 버전은 인증 대상이 아니므로 같은 엔드포인트·계정이면 비밀번호를 재사용할 수 있다. 원격 데이터 영역 변경에 대한 기존 초기 비교 정책은 그대로 적용한다.
- URL·계정이 바뀌면 즉시 현재 메모리 인증과 이전 연결의 자동 로드를 해제한다. 이전 비밀번호를 새 주소에 시험 전송하지 않는다. 기존 보관 항목은 비활성 목록에 남기고 설정에서 대상별로 삭제할 수 있게 한다.
- 상태 폴더를 다른 PC·OS 사용자에게 복사해도 비밀번호 이동을 보장하지 않는다. 보관 항목을 못 찾으면 새로 입력하고 저장하도록 안내한다. 다른 상태 폴더의 항목을 검색해서 대신 사용하지 않는다.
- 비밀번호는 공백을 trim하지 않으며 유니코드를 그대로 취급한다. 빈 문자열은 명시적으로 거부하고 공통 상한은 UTF-8 기준 4 KiB로 둔다. 저장 어댑터도 같은 바이트 형식으로 처리한다.

## 4. 웹 설정과 사용자 흐름

### 최초 저장·비밀번호 변경

1. 기존 서버 URL·계정을 저장한다. 다른 설정의 일반 저장 버튼이 비밀번호 저장을 암묵적으로 실행하지 않도록 인증 영역을 분리한다.
2. 비밀번호 입력 아래에 **이 기기에 안전하게 저장 — 선택** 체크박스를 둔다. 기존 사용자의 선택을 임의로 켜지 않으며 최초 기본값은 해제한다.
3. 사용할 수 있는 보관함 이름과 재시작 후 자동 인증 가능 여부를 표시한다. 보관함을 사용할 수 없으면 저장 옵션을 비활성화하고 이유 및 세션 입력 방법을 표시한다.
4. **연결 확인 후 적용**을 누르면 후보 비밀번호로 기존 전용 테스트 경로의 연결 테스트를 수행한다. 실제 세이브는 건드리지 않는다.
5. 성공하면 체크 여부에 따라 세션 메모리 또는 OS 보관함에 적용한다. 실패하면 기존 정상 비밀번호·보관 항목을 교체하지 않는다. 네트워크·TLS 실패도 잘못된 비밀번호로 단정하지 않는다.
6. OS 저장은 성공했는지 확인한 뒤 완료로 표시한다. 연결은 성공했지만 저장이 실패하면 이를 구분하고 **세션에서만 사용**을 별도 선택할 수 있게 한다.
7. 처리 후 입력란을 비운다. 저장된 원문 읽기·미리 채우기·비밀번호 보기 API는 제공하지 않는다.

체크 해제는 앞으로 입력하는 비밀번호의 저장 방식만 선택한다. 기존 보관 항목을 조용히 지우지 않는다. 세션 전용 비밀번호가 기존 저장값과 다르면 “이번 실행만 사용, 다음 실행에는 기존 저장값 사용”을 표시하며, 영구 교체 또는 삭제 방법을 안내한다.

### 다음 실행과 Steam 사용

- 시작 시 현재 연결의 저장값을 프롬프트 없이 읽어 준비한다. 아직 서버 요청을 하지 않았으면 **저장값 불러옴·연결 미확인**으로 표시한다.
- Steam 런처의 실행 전 동기화도 같은 인증 관리자를 사용한다. 저장값을 읽을 수 있으면 브라우저 입력 없이 기존 동기화→게임 실행→종료 후 동기화 흐름을 따른다.
- 읽기에 OS 프롬프트가 필요하면 백그라운드 시작이나 Gaming Mode에서 창을 무작정 띄우지 않는다. **보관함 잠금 해제 필요**로 보류하고 Desktop Mode의 설정에서 **저장된 비밀번호 사용**을 누르게 한다. 사용자가 요청한 해제에만 OS 프롬프트를 허용하고 취소·시간 초과를 처리한다.
- 비밀번호 읽기와 OS 프롬프트 대기는 각각 제한 시간을 갖는다. 자동 읽기는 최대 5초, 사용자가 시작한 프롬프트는 최대 60초를 기본값으로 검증하며 무한 대기를 허용하지 않는다.
- 자격 증명을 못 얻으면 에뮬레이터 실행 전에 중지한다. 오프라인 플레이 선택은 이번 작업에 포함하지 않는다. 종료 후 인증 실패는 기존 미전송 보존 흐름으로 처리한다.
- 절전 복귀 후 OS 저장소가 다시 잠겨 있을 수 있다. 이미 메모리에 있는 비밀번호를 계속 사용하는 것은 허용하되, 저장소에서 새로 읽을 때는 잠금 상태를 다시 확인한다.

### 사용 중지·삭제

| 동작 | 현재 실행 | OS 보관함 | 다음 실행 |
|---|---|---|---|
| 현재 세션 잠금 | 메모리 참조 제거, 자동 재조회도 차단 | 유지 | 다시 자동 읽기 가능 |
| 저장된 비밀번호 삭제 | 해당 연결의 모든 인증 사용 중지 | 해당 항목 삭제 | 다시 입력 필요; 환경변수는 별도 |
| 저장된 비밀번호 사용 | 명시적 재조회·필요한 OS 해제 | 유지 | 기존 정책 유지 |

게임 실행·동기화 작업 중에는 비밀번호 교체·잠금·삭제·연결 변경을 막고 종료 후 수행하도록 한다. 읽기 전용 상태 조회는 허용한다. 삭제는 기존 확인 UI에서 대상 연결을 명시하며 성공 여부를 확인한다. 실패하면 “삭제됨”으로 표시하지 않고 재시도할 수 있게 한다. 메모리 참조 제거가 .NET 문자열의 즉각적인 물리 메모리 삭제를 보장한다는 표현은 사용하지 않는다.

## 5. 백엔드 구조와 API

- `CredentialManager`: 연결별 인증 소스 결정, 상태 전이, 세션 잠금, 검증 후 적용과 변경 직렬화.
- `ICredentialStore`: capability, read, write, delete. 결과는 `missing`, `locked`, `unavailable`, `denied`, `error` 등을 구분하고 비밀을 로그로 출력하지 않는다.
- `WindowsCredentialStore`, `SecretServiceCredentialStore`, 테스트용 fake 구현. UI와 동기화 엔진은 OS API를 직접 호출하지 않는다.
- `Coordinator.Store()`는 현재 연결에 묶인 인증 임대값을 받아 WebDAV 어댑터를 만든다. 저장 비밀번호를 시작할 때 한 번 읽는 것만으로 설정 변경·legacy import 이후의 잘못된 재사용을 막을 수 없으므로 매 획득 시 연결 식별자를 확인한다.
- 기존 `HasCredential`은 호환 표시로 유지하되 실제 인증 성공과 구분한다. `source`는 `none/session/environment/os-store`, 보관함 상태와 마지막 연결 검증 결과는 별도 필드로 제공한다.

실제 클래스명은 `Credentials`이며 `Coordinator`의 작업 gate로 인증 변경을 직렬화한다. 비밀번호 검증·적용 중 서버 설정이 변경되지 않도록 하고 요청의 연결 ID도 확인한다. 동기화가 진행 중이면 인증 변경은 대기 적용하지 않고 거부한다.

| API 초안 | 입력·동작 | 응답 |
|---|---|---|
| `GET /api/storage/credential` | 현재 연결의 capability·상태 조회 | source, provider, saved, ready, storeState, verification, 안내 코드 |
| `POST /api/storage/credential/probe` | 사용자 요청으로 OS 보관함 capability 재확인 | 비밀 없는 상태; 자동 잠금 해제 없음 |
| `PUT /api/storage/credential` | password, persist, expectedConnectionId; 후보 검증 후 적용 | 비밀 없는 상태 |
| `POST /api/storage/credential/unlock` | expectedConnectionId; 저장값 조회·명시적 OS 해제 | 비밀 없는 상태 |
| `POST /api/storage/credential/lock` | 현재 세션 인증 사용 중지 | 비밀 없는 상태 |
| `DELETE /api/storage/credential` | expectedConnectionId; 현재 저장값 삭제 | 삭제 결과와 상태 |
| `GET /api/storage/credential/retired` | 이 상태 폴더에서 보관한 비활성 연결 조회 | 불투명 record ID와 마스킹한 연결 설명 |
| `DELETE /api/storage/credential/retired/{id}` | 이 namespace의 해당 비활성 항목 삭제 | 비밀 없는 결과 |

기존 `/api/storage/unlock`은 세션 전용 입력 호환 경로로 유지한다. 잠금·삭제 이후의 명시적 세션 입력은 재사용을 허용한다. 모든 변경 API는 기존 Host·Origin·세션 검증을 유지하고 원문 비밀번호를 반환하지 않는다. 클라이언트가 제출한 임의 OS 항목 ID로 접근하지 않는다. 긴 검증 중 연결 설정이 바뀌면 `expectedConnectionId`를 다시 비교하여 적용을 거부한다.

구현 API의 DELETE 요청은 본문 대신 `?connectionId=<expectedConnectionId>`를 사용한다. 이 값은 비밀번호가 아닌 연결 식별 해시다.

### 인증 소스 우선순위와 기존 환경변수

명시적으로 입력한 현재 세션 비밀번호 → 비어 있지 않은 `RYUSYNC_WEBDAV_PASSWORD` → 현재 연결의 OS 저장값 순서로 사용한다. 환경변수는 시작 시 설정된 연결에만 묶으며 연결 변경·legacy import에서 무조건 다시 읽어 새 주소에 보내지 않는다. 환경변수를 자동으로 OS 보관함에 복사하지 않는다.

환경변수가 우선 사용 중이면 웹에 이를 표시한다. 저장값 삭제는 외부 실행 환경의 변수를 지우지 못하므로 현재 세션은 잠그고, 다음 프로세스 시작에서는 환경변수가 다시 유효할 수 있음을 명시한다. 사용자가 환경변수를 제거한 다음 저장값 자동 사용을 검증하도록 안내한다.

### 저장 도중 종료·실패

OS 보관함과 SQLite는 하나의 트랜잭션이 아니다. 교체 시 새 버전의 불투명 항목 ID를 만든 뒤 **비밀 없는 작업 기록 → 새 항목 쓰기·읽기 확인 → DB의 활성 참조 교체 → 이전 항목 정리** 순서로 처리한다. 실패 시 이전 정상 참조는 유지하고, 남은 임시 항목은 다음 시작에서 namespace 내의 기록된 대상만 정리한다. 삭제도 정리 대기 상태를 기록해 중단 후 재시도하며, 미완료 삭제 항목을 자동 인증에 쓰지 않는다. 재시작 시 복구를 위해 비밀번호 자체를 저널에 쓰지 않는다.

## 6. 인증 실패와 정보 노출 방지

| 상황 | 처리 |
|---|---|
| OS 보관함 잠김·OS 해제 취소 | 저장값 유지, 해제 필요 표시, 동기화·실행 보류 |
| Secret Service 없음·D-Bus 없음 | 서비스 이용 불가 표시, 세션 입력 가능 |
| HTTP 401 | 재인증 필요 표시, 같은 비밀번호 자동 반복 제출 중지, 저장값 자동 삭제 금지 |
| HTTP 403 | 권한 또는 서버 정책 문제로 안내, 비밀번호 오류로 확정하지 않음 |
| TLS·DNS·연결 시간 초과 | 네트워크 오류로 안내, 저장값·인증 실패 판단과 분리 |
| OS 항목 없음·삭제됨 | 다시 입력 필요, 다른 연결의 비밀번호로 대체 금지 |
| 저장·삭제 중 OS 권한 오류 | 실패 상태를 유지하고 명시적 재시도 제공 |

비밀번호를 URL·명령 인수·브라우저 localStorage/sessionStorage·일반 설정·SQLite·로그·오류 본문·작업 기록에 남기지 않는다. 웹 입력은 기존 loopback 인증 API 본문으로만 전달한다. 로그 내보내기와 추후 설정 백업에서도 인증값을 제외한다. OS 보관함은 각 기기에서 설정하며 WebDAV 세이브와 함께 동기화하지 않는다.

## 7. 기존 사용자와 배포

- 기존 세션·환경변수 사용은 유지한다. 업데이트했다고 현재 메모리 비밀번호를 자동 영구 저장하지 않는다.
- 상태 스키마에 비밀 없는 인증 metadata만 추가한다. v1/v2 세이브 포맷을 바꾸거나 기존 baseline을 초기화하지 않는다.
- legacy import는 세이브 연결·설정만 가져오며 다른 상태 폴더의 OS 비밀번호 참조를 가져오지 않는다.
- 앱 폴더 교체 시 같은 상태 폴더·OS 사용자를 유지하면 저장값을 다시 찾을 수 있어야 한다.
- OS 보관 항목을 직접 제거했을 때도 앱이 비정상 종료되지 않아야 한다. 앱 삭제 전에 웹에서 해당 기기의 저장값을 지우는 방법과 잔여 항목 정리 방법을 README에 추가한다.
- Windows·linux-x64 배포 모두 필요한 의존성을 포함하고, SDK·개발용 CLI 도구가 없는 환경에서 테스트한다. Secret Service 구현 자체의 설치 여부는 별도이며 self-contained 배포가 이를 자동 제공하는 것은 아니다.

## 8. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 저장 인터페이스·상태 모델·연결 식별 규칙 | fake 보관함으로 연결 분리·소스 우선순위·실패 복구 테스트 |
| 2 | Windows 어댑터 | 동일 사용자에서 저장·재시작·변경·삭제 확인, 다른 연결로 미전송 |
| 3 | Linux Secret Service 어댑터 | 서비스 유무·잠금·프롬프트 취소·D-Bus 오류 처리와 패키징 확인 |
| 4 | Coordinator·API 통합 | 웹과 Steam 런처에서 같은 인증 사용, active job 중 변경 차단 |
| 5 | 설정 UI·기존 버전 이전 안내 | 선택 저장·상태 구분·세션 잠금·현재 및 비활성 항목 삭제 가능 |
| 6 | 양 OS 실기·문서 갱신 | 아래 시나리오 통과, 지원 조건 및 제한을 README에 명시 |

필수 검증 시나리오:

1. Windows에서 한 번 저장한 뒤 백엔드 종료·재로그인·재부팅 후 브라우저 입력 없이 Steam 전·후 동기화가 된다.
2. SteamOS Desktop Mode에서 저장한 뒤 Gaming Mode·재부팅·절전 복귀에서 자동 읽기 가능 여부를 확인한다. 실제 환경에서 불가능하면 원인과 세션 해제 절차를 표시하며 “자동 로그인 지원 완료”로 표기하지 않는다.
3. 일반 Linux의 이용 가능한 Secret Service와 없는 환경 모두 실행되며 평문 fallback이 생성되지 않는다.
4. 비밀번호·서버 계정 변경, 잘못된 후보 입력, TLS 실패, OS 쓰기 실패에서 기존 정상 저장값을 보존한다.
5. URL·계정 변경·legacy import·다중 상태 폴더에서 기존 비밀이 다른 연결로 전송되지 않는다.
6. 메모리 잠금 후 주기적 상태 조회·수동 동기화·Steam 요청이 자동으로 잠금을 풀지 않는다.
7. 저장값 삭제·삭제 도중 종료·외부 OS 항목 삭제 후 재시작이 안전하며, 삭제된 항목은 재사용하지 않는다.
8. 환경변수 우선 사용 및 저장값 삭제 후의 차이를 안내하고, 환경변수 제거 후 OS 자동 인증을 별도로 확인한다.
9. API·DB·로그·내보내기·브라우저 저장소에 테스트 비밀번호가 남지 않는다. 프로세스 메모리 사용과 HTTP 요청 본문은 이 검사에서 구분한다.
10. 기존 동기화·충돌·백업·게임 실행 테스트가 계속 통과하며 저장소 스키마·원격 revision이 유지된다.

자동 테스트는 fake 및 격리된 테스트 보관 항목을 사용한다. 일반 개발·CI에서 사용자의 실제 보관함을 비우거나 임의 항목을 수정하지 않는다. 실기 테스트 항목도 테스트 namespace만 정리한다.
