# SteamOS용 설정·동기화 UI 기획

2026-10-25 · 초기 시안 및 Steam 실행을 고려한 구현 기획. 하단 보완·구현 절에 실제 구현 범위와 남은 검증을 기록한다. 아직 새 릴리스로 배포하지 않았다.

## 목표와 시안 열기

Steam Deck의 1280×800 가로 화면을 기준으로 터치·트랙패드·키보드로 설정하고 동기화할 수 있는 추가 화면을 제공한다. PC용 상세 화면은 유지한다. `index.html`을 브라우저에서 열면 동기화, 설정 4개 분류, 충돌 비교 화면을 직접 조작할 수 있다. 모든 게임·주소·시각은 샘플이다. 외부 리소스·API 요청·실제 저장·동기화는 없다.

## 정보 구조

- 상단 고정: RyuSync, 동기화/설정 탭, 기기 이름과 서버 인증 상태.
- 본문: 1280×800 기준 좌우 여백 32px, 콘텐츠 영역 624px. 내용이 많으면 본문만 스크롤한다.
- 하단 고정: 현재 화면의 주 동작, 조작 안내. 설정 저장과 비밀번호 적용은 구분한다.
- 낮은 높이의 창·브라우저 툴바가 있는 경우 스크롤을 허용하고, 950px 이하에서는 세로 배치한다.
- 명시적인 ‘Deck 화면 / 상세 화면’ 전환을 제공한다. 화면 너비만으로 PC 사용자의 UI를 강제 변경하지 않는다.

## 동기화 화면

왼쪽은 게임별 세이브 상태, 오른쪽은 전체 요약과 동기화 버튼이다. 게임 이름·프로필·설치본을 식별할 수 있게 하고 같은 게임의 복수 프로필/설치본을 합쳐서 숨기지 않는다. 샘플 아이콘은 기획용이며 구현 시 기존 썸네일 캐시를 사용한다.

| 상태 | 표시·동작 |
|---|---|
| 아직 비교하지 않음 | ‘확인 필요’. 서버를 조회하기 전에 ‘동기화됨’이라고 표시하지 않음 |
| 이전 비교 결과 있음 | 마지막 확인 시각 표시. 서버 변경/이 기기 변경은 다음 비교에서 달라질 수 있음 |
| 동기화 중 | 실제 작업 단계와 처리 게임 수 표시. 서버가 바이트 진행률을 제공하지 않으면 퍼센트를 꾸며내지 않음 |
| 내용 일치 | ‘동기화됨’. 전체 성공 시 준비 완료 표시 |
| 충돌 | 해당 게임은 적용 보류. 두 버전 비교와 최종 확인 화면으로 이동 |
| 에뮬레이터 실행 중 | ‘게임 종료 후 동기화 예약’으로 주 버튼 변경. 실제 큐 정책과 일치시키기 |
| 비밀번호 필요 | ‘비밀번호 설정’으로 연결. 저장값 존재와 서버 인증 성공은 별개로 표시 |
| 네트워크 오류 | 기존 세이브 유지, 오류 이유와 재시도 표시. 일부 성공/실패를 구분 |
| 등록된 게임 없음 | ‘설치본 설정·게임 탐색’ 안내. 비어 있는 전체 동기화 버튼 대신 시작 동작 제공 |

‘전체 동기화’는 현재 엔진의 비교·업로드·다운로드 정책을 사용하며 최신 시각만으로 덮어쓰지 않는다. 시안의 완료 애니메이션은 데모이며 실제 진행률 구현이 아니다. 서버 게임 목록·이력·백업은 상세 화면 연결로 유지한다. 게임 행에서 선택 동기화·상세 정보를 여는 흐름은 제품 구현 때 추가한다.

## 설정 화면

왼쪽 분류, 오른쪽 편집 카드, 하단 저장 버튼을 사용한다. 각 분류에서 필수 입력과 현재 상태를 보여준다.

| 분류 | 기본 표시 | 주 동작 |
|---|---|---|
| 서버 연결 | WebDAV URL, 계정, 동기화 공간, 인증 상태 | 설정 저장·연결 확인 |
| 비밀번호 | 파일 평문/OS 보관함/세션 선택, 새 암호 입력 | 비밀번호 적용·연결 확인 |
| 에뮬레이터 | 설치본 선택, 데이터 루트, 실행 파일 | 저장 후 게임 탐색 |
| Steam 실행 | 실행 프로필과 시작 전/종료 후 처리 흐름 | 프로필 설정, 등록 방법 안내 |

- 비밀번호 선택의 기본값은 기존 정책을 유지한다. 시안의 ‘파일 저장됨’은 사용자가 이미 선택한 경우의 예시다.
- 평문 저장 설명은 선택 영역 가까이에 표시한다. 기존 암호를 입력란에 채워 넣거나 반환하지 않는다.
- 현재 세션 잠금·저장값 삭제·이전 연결 정리는 ‘비밀번호 관리’의 추가 영역으로 제공한다. 삭제에는 기존 확인 절차를 적용한다.
- Ryujinx 데이터 루트는 `~/.config/Ryujinx`와 같이 최상위 폴더임을 안내한다. Yuzu 선택 시 데이터/NAND 입력 규칙을 적용한다.
- 빌드·커스텀 NAND·작업 폴더·실행 인수 등은 ‘고급 설정’으로 이동한다. 필수 입력은 숨기지 않는다.
- 변경한 채 분류·화면을 이동하면 저장/계속 편집/변경 버리기 선택을 제공한다. 시안의 샘플 입력은 실제 저장되지 않는다.
- 인증 실패 시 입력을 그대로 반복하지 않도록 서버 연결 오류와 암호 저장 오류를 분리한다.

## 충돌 화면

게임·프로필을 제목에 표시하고 이 기기/서버 버전을 나란히 비교한다. 기기, 에뮬레이터·게임 버전, 기록 시각과 제공 가능한 파일 수·크기를 보여준다. 플레이 진행도는 세이브를 해석하지 않으므로 추정하지 않는다. 시각은 ‘수정/업로드/발견’ 등 실제 의미를 구분한다.

선택 → 최종 적용의 두 단계로 구성하며 ‘나중에 결정’으로 빠져나올 수 있다. 적용 직전 현재 엔진의 기준 해시·원격 head 재검증을 사용한다. 오래된 선택이면 다시 비교한다. 두 버전보다 많은 원격 분기가 있으면 가로 넘침 없이 목록을 스크롤한다.

## 시각·입력 규칙

- 기존 초록 계열을 유지한 어두운 배경, 연한 민트 주 버튼, 충돌/주의는 황색. 상태는 색뿐 아니라 아이콘과 문구로 구분한다.
- 제목 30px, 카드 제목 20px, 일반 입력 16~18px, 보조 14px 이상을 기본으로 한다. 실제 7인치 화면에서 가독성을 검증한다.
- 기본 터치 대상 높이 52px, 입력 54px, 버튼 사이 최소 12px. 긴 게임명·경로는 줄바꿈 또는 상세 영역을 제공한다.
- 키보드 Tab/Shift+Tab, Enter, Esc와 명확한 포커스 표시. 모달은 배경 입력을 차단하고 포커스를 내부에 유지한다.
- 컨트롤러 목표: 방향키 이동, A 선택, B 뒤로. 일반 브라우저는 게임패드 입력을 자동 지원하지 않으므로 Steam Input 매핑 또는 Gamepad API 구현·검증 전에는 A/B 안내를 표시하지 않는다. 시안은 터치·키보드만 구현한다.
- 화면 키보드가 올라오면 입력란과 확인 버튼이 보이도록 본문 스크롤을 조절한다. Desktop Mode 브라우저와 Gaming Mode 브라우저/호스트 실행 방식은 각각 실기기에서 확인한다.

## 구현 순서와 완료 기준

1. 기존 React 앱에 명시적 Deck 레이아웃 선택을 추가하고 API·저장소·세이브 엔진을 공유한다. 별도 서버는 만들지 않는다.
2. 기존 상태/작업/세이브 목록/설정/인증 API를 연결한다. 게임별 변경 방향 사전 표시에 필요한 읽기 전용 비교 요약을 검토한다. 현재 작업 결과만으로 실시간 원격 상태라고 표시하지 않는다.
3. 충돌·오프라인·인증 필요·실행 중·빈 목록 상태를 구현하고, 기존 상세 화면으로 연결한다.
4. 실제 Steam Deck에서 1280×800, 툴바가 있는 1280×720 영역, 화면 키보드, 긴 한글 게임명, 30개 게임, 컨트롤러 포커스, 모드 전환을 확인한다.

완료 기준: 가로 스크롤 없이 핵심 동작에 접근하고, 설정 저장과 비밀번호 적용 결과가 명확하며, 충돌을 임의로 덮어쓰지 않고, 게임 중에는 기존 동기화 안전 규칙을 유지한다. 기존 PC 화면과 자동 실행 프로필에 회귀가 없어야 한다.

## 초기 시안 산출물 범위

`index.html`: 정적 인터랙티브 시안. `sync.png`, `settings.png`, `conflict.png`: 1280×800 캡처. 제품 코드·서버 설정·실제 세이브에는 변경 없음. 자동 실행, 사용자 서비스, 게임패드 지원 자체는 이번 시안의 구현 범위가 아니다.

## 2026-10-25 보완·구현: Steam 바로가기와 인증

사용자 요청에 따라 정적 시안을 실제 React 앱과 연결했다. Windows의 기본 UI는 유지하며 ‘Deck 화면 / 기존 화면’ 전환을 추가했다. 화면 선택만 브라우저 localStorage에 저장한다. 토큰이나 WebDAV 비밀번호는 저장하지 않는다. 같은 백엔드·주소·설정·동기화 엔진을 사용하며 `?ui=deck`으로 Deck 레이아웃을 지정할 수 있다.

### 실행 모드

| 명령 | 동작 |
|---|---|
| `serve` / 인자 없음 | 기존 백엔드 실행 유지 |
| `open` | 기본 브라우저에 새 일회용 인증 링크 열기 |
| `deck` | 백엔드 연결 또는 시작 → 새 토큰 → Deck 앱 창 → 창 종료까지 런처 대기 |
| `launch --deck [--launch-profile ID]` | 기존 게임 전·후 동기화. 실패/충돌 시 그 시점에 새 토큰을 받아 Deck 앱 창으로 안내 |

Steam 설정 화면용 바로가기는 실행 파일과 `deck`만 등록한다. URL·토큰을 고정 저장하지 않는다. 게임용 바로가기는 `launch --deck`을 사용한다. 문제 해결 후 게임은 자동 재실행하지 않으며 Steam 바로가기를 다시 실행한다.

앱 창은 설치된 Chromium/Chrome/Edge의 앱 모드를 사용한다. Linux의 네이티브 Chromium/Chrome 및 Flatpak `org.chromium.Chromium`/`com.google.Chrome`, Windows의 Chrome/Edge를 탐색한다. `--browser`로 네이티브 Chromium 계열 실행 파일의 절대 경로를 지정할 수 있다. 브라우저 자동 설치는 하지 않는다. 설치되지 않았다면 Desktop Mode의 Discover에서 Chromium을 설치하도록 안내한다.

실행마다 별도 임시 브라우저 프로필을 사용하므로 이미 열린 기본 브라우저에 창을 넘기지 않는다. 브라우저 프로세스가 끝날 때까지 런처가 대기하고 일반 종료 시 임시 프로필 정리를 시도한다. Flatpak에는 이 프로필 폴더만 추가로 공유하며 세이브/상태 폴더 전체 접근은 부여하지 않는다. 강제 종료 시 임시 프로필이 남을 수 있다. 인증 링크는 기존의 5분·1회용이며 게임을 오래 실행한 뒤 오류가 나더라도 UI를 여는 순간에 발급한다. [Chromium 프로필](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/user_data_dir.md), [Flatpak 권한](https://docs.flatpak.org/en/latest/sandbox-permissions.html).

일반 창 닫기는 공유 백엔드를 종료하지 않는다. Steam의 강제 중지는 자식 백엔드에도 영향을 줄 수 있으므로 계속 사용할 백엔드는 기존 사용자 systemd 서비스로 실행하는 구성을 권장한다. 같은 사용자·상태 폴더를 지정한다. Gaming Mode 전환·화면 포커스·Steam 강제 종료·Flatpak 실제 런타임은 실기기 검증이 필요하다.

### 실제 연결 범위와 시안 차이

- 동기화 화면은 실제 등록 목록, 최근 작업 결과, 실행 세션과 인증 준비 상태를 표시한다. 원격 상태를 새로 조회한 척하지 않으며, 첫 실행은 ‘아직 확인하지 않음’, 기존 결과는 작업 시각을 표시한다.
- 전체/개별 동기화와 게임 종료 후 예약은 기존 API를 호출한다. 실제 처리 결과 개수를 표시하고 가짜 전송 퍼센트는 사용하지 않는다.
- 서버 설정·비밀번호 저장·Ryujinx/Yuzu 설치본 추가/편집·게임 탐색을 연결했다. 기존 상세 화면으로 게임 등록·서버 목록·실행 프로필·이력·백업을 이어서 사용할 수 있다.
- 충돌 화면은 기존 해시·head 재검증을 유지하고 선택 후 ‘선택한 버전 적용’으로 최종 확인한다. 교차 에뮬레이터 호환성 승인도 기존 절차를 사용한다.
- 방향키로 버튼 간 포커스를 이동하고 Tab/Enter/Esc를 지원한다. 입력란의 방향키는 편집용으로 유지한다. 모달은 배경 입력 차단과 포커스 제한을 적용한다. 컨트롤러는 Steam Input에서 방향키/Enter/Esc로 매핑한다. 직접 Gamepad API 지원을 제공한다고 표시하지 않는다.
- Deck 창의 브라우저 프로필은 임시이므로 실행할 때마다 `?ui=deck`으로 지정한다. 기존 브라우저에서 수동 선택한 레이아웃은 해당 브라우저에 유지된다.
- 일부 분류는 내용이 길어 본문 스크롤을 사용한다. 화면 키보드와 긴 경로를 고려해 하단 동작은 별도 영역에 배치한다.

### 검증

.NET 테스트, 프론트엔드 빌드와 함께 `tests/deck_launcher_integration.py`에서 두 번 실행 시 새 일회용 토큰·재사용 거부·창 대기·프로필 정리·공유 백엔드 보존을 검증한다. `tests/deck_ui.py`는 1280×800/720에서 설정 저장, 인증 UI, 동기화·종료 후 예약, 충돌 최종 확인, 빈 목록, 기존 UI 전환을 브라우저로 확인한다. 모의 WebDAV/게임 데이터와 임시 상태 폴더만 사용한다. `implemented-*.png`는 실제 React 화면의 테스트 데이터 캡처다. 원래 `sync/settings/conflict.png`는 초기 디자인 시안으로 유지한다.
